# إدارة المال

تطبيق ويب شخصي لإدارة الراتب والمصروفات اليومية والصناديق، مبني بالكامل بـ **HTML و CSS و JavaScript** فقط.
لا يحتاج إلى خادم أو قاعدة بيانات أو تسجيل دخول، ويعمل مباشرة على **GitHub Pages** وبدون إنترنت بعد أول فتح.

## المميزات

- **شهر مالي يبدأ من يوم الراتب** (مثال: 27 سبتمبر ← 26 أكتوبر) مع حفظ جميع الشهور السابقة.
- **ميزانية يومية ذكية**: (الراتب − المصاريف الشهرية الثابتة − المبلغ المستهدف) ÷ عدد أيام الشهر.
  - الفائض ينتقل لليوم التالي (200 + 50 = 250) أو يوزع على باقي الأيام (قابل للاختيار من الإعدادات).
  - التجاوز يقلل ميزانية الأيام القادمة تلقائيًا.
  - إذا بدأت الاستخدام في منتصف الشهر، تُحسب الميزانية من يوم البدء مع إمكانية إدخال ما صرفته قبل ذلك.
- **مؤشرات الحالة**: 🟢 ضمن الميزانية · 🟡 اقتربت من الحد · 🔴 تجاوزت الميزانية.
- **إضافة مصروف سريعة** (المبلغ، التصنيف، الوصف، التاريخ) مع تعديل وحذف وبحث وتصفية حسب التاريخ والتصنيف.
- **تصنيفات جاهزة** 🍔 ⛽ 🏠 🛍️ 🚗 ☕ 🎮 💊 👕 📱 📦 مع إمكانية إضافة تصنيفات مخصصة.
- **المصاريف الشهرية الثابتة** (إيجار، أقساط، فواتير...) مع تتبع المدفوع وغير المدفوع لكل شهر.
- **الأموال الإضافية** (مكافأة، هدية، دخل إضافي، استرداد مبلغ...) في رصيد منفصل لا يؤثر على الميزانية تلقائيًا.
- **الصناديق**: صندوق الطوارئ وصندوق الاستثمار، مع الإيداع والسحب وسجل كامل. التحويل للصناديق لا يقلل الميزانية اليومية.
- **صفحة الشهور** وتفاصيل كل شهر يومًا بيوم.
- **التحليل**: الإجماليات، متوسط الصرف اليومي، أكثر تصنيف، أعلى يوم، أيام الفائض والتجاوز، ورسوم بيانية.
- **النسخ الاحتياطي**: تصدير واستيراد ملف `money-management-backup.json`، وحذف كل البيانات مع تأكيد.
- واجهة عربية RTL، متجاوبة (Mobile First)، وضع داكن، وتعمل دون اتصال (Service Worker).
- العملة: الريال السعودي فقط، بتنسيق مثل `15,000 ر.س` و `1,500.50 ر.س`.

## هيكل المشروع

```
index.html      الصفحة الرئيسية وهيكل التطبيق
style.css       التصميم الكامل (فاتح/داكن، جوال/كمبيوتر)
script.js       منطق التطبيق كاملًا
sw.js           Service Worker للعمل دون إنترنت
manifest.json   بيانات تثبيت التطبيق على الجوال
assets/icons/   أيقونة التطبيق
README.md       هذا الملف
```

## التشغيل محليًا

- الطريقة الأبسط: افتح ملف `index.html` مباشرة في المتصفح.
- أو شغّل خادمًا محليًا بسيطًا (لتفعيل العمل دون إنترنت):
  ```bash
  python3 -m http.server 8000
  ```
  ثم افتح `http://localhost:8000`.

> ملاحظة: البيانات محفوظة لكل متصفح وعنوان على حدة؛ البيانات في `file://` تختلف عن `localhost` وعن GitHub Pages. استخدم التصدير والاستيراد لنقلها.

## الرفع إلى GitHub

1. أنشئ مستودعًا جديدًا على [github.com](https://github.com/new) (مثلًا `money-management`).
2. ارفع الملفات من زر **Add file ← Upload files** واسحب كل محتويات المجلد (مع مجلد `assets`)، ثم **Commit changes**.
   أو عبر سطر الأوامر:
   ```bash
   git init
   git add .
   git commit -m "إدارة المال"
   git branch -M main
   git remote add origin https://github.com/USERNAME/money-management.git
   git push -u origin main
   ```

## تفعيل GitHub Pages

1. من المستودع افتح **Settings ← Pages**.
2. في **Source** اختر **Deploy from a branch**.
3. اختر الفرع `main` والمجلد `/ (root)` ثم **Save**.
4. بعد دقيقة تقريبًا سيعمل التطبيق على:
   `https://USERNAME.github.io/money-management/`

جميع المسارات في المشروع نسبية، لذلك يعمل التطبيق داخل أي مجلد فرعي دون تعديل.

## حفظ البيانات (LocalStorage)

كل البيانات تُحفظ داخل متصفحك فقط، ولا تُرسل لأي جهة. المفاتيح المستخدمة:

| المفتاح | المحتوى |
|---|---|
| `mm_settings` | الراتب، يوم الراتب، المبلغ المستهدف، طريقة الترحيل، المظهر |
| `mm_months` | الشهور المالية وبيانات كل شهر |
| `mm_transactions` | المصروفات والتحويلات والسحوبات |
| `mm_fixedExpenses` | قائمة المصاريف الشهرية الثابتة |
| `mm_extraIncome` | الأموال الإضافية |
| `mm_funds` | صندوق الطوارئ وصندوق الاستثمار |
| `mm_categories` | التصنيفات (الافتراضية والمخصصة) |

> مسح بيانات المتصفح أو استخدام التصفح الخفي يحذف البيانات؛ احرص على التصدير بشكل دوري.

## النسخ الاحتياطي والاستعادة

- **التصدير**: الإعدادات ← النسخ الاحتياطي ← **تصدير** — يتم تنزيل `money-management-backup.json`.
- **الاستيراد**: الإعدادات ← **استيراد** واختر الملف. يتم التحقق من الملف قبل استبدال البيانات الحالية.
- **حذف كل البيانات**: الإعدادات ← منطقة الخطر، ويتطلب كتابة كلمة «حذف» للتأكيد.

## تحديث التطبيق

عند تعديل الملفات ورفعها من جديد، غيّر رقم الإصدار في `sw.js` (`money-management-v1` ← `v2`) ليحصل المستخدمون على النسخة الجديدة مباشرة.
